# Mapping: Team Contracts → L2 Authoritative Contract Registry + L3 Read-Only Copies (CONTRACT-FIRST)

## Purpose

In a multi-workspace generation, build the **authoritative contract registry** in the Layer-2 control plane and push a **read-only, version-pinned copy** of the relevant contracts into each Layer-3 per-team workspace. Contract-first is the seam: the ONLY sanctioned coupling between isolated per-team workspaces is a published, versioned contract. This is what makes team isolation safe.

**Output:**
- L2 authoritative registry: `{project_root}/{slug}-management/contracts/` (`registry.yaml` + per-service/context contract files).
- L3 read-only copies: `{project_root}/{slug}-workspaces/{team}/contracts/` (only the contracts that team produces + consumes, version-pinned).

**Condition:** Generate IF `workspaceTopology ∈ {per-team, hybrid}` (Config Gate Q4). SKIP for `single`.

**Cluster:** Multi-workspace (Layer-2 control plane + push-down to L3).

> **Layer discipline:** the authoritative registry is a **Layer-2** artifact (governed by the architects/owners). Each L3 workspace receives a **read-only, version-pinned copy** of what it produces + consumes — a team cannot edit contracts it does not own. A team's need to change a shared contract surfaces as drift that L2 observes (read-down) and re-governs, then DWG re-pushes — preserving the one-way boundary.

## MANDATORY: Stage Sub-Role — API Designer + Team Topology Architect

API Designer (contract-first, versioning, compatibility) layered with Team Topology Architect (`#persona-subrole-team-topology-architect` — who owns which contract). ADDS a dimension — does NOT replace the primary role.

### Behavioral Shifts
- Every seam between teams is a published, versioned contract — never shared source or a shared database.
- A contract is owned by exactly one (producing) team; consumers pin a version.
- Generate only the contract formats the AP actually uses (no speculative contracts).

### Anti-Patterns
- Do NOT let a consuming team hold an editable copy of a contract it does not own (copies pushed to L3 are READ-ONLY).
- Do NOT invent contracts not present in the AP (Stage 10 API architecture / Stage 11 integration).
- Do NOT place the authoritative registry inside an L3 workspace (it is L2).

    format: openapi

### L3 Read-Only Copy — `{slug}-workspaces/{team}/contracts/`

Each team workspace receives a **read-only** copy of the contracts it **produces** (editable at the L2 source only) + the contracts it **consumes** (pinned version). A header marks them read-only:

```yaml
# READ-ONLY copy — authoritative source: {slug}-management/contracts/{svc}/...
# This team CONSUMES this contract at the pinned version below. To change a
# contract you OWN, edit the L2 authoritative registry (drift surfaces to L2).
# pinnedVersion: {semver}
```

## Transformation Rules

### Rule 1: One Owner Per Contract
Each contract is owned by exactly one producing team (from `team-context-registry`). The registry records the owner; only the owner's edits at L2 are authoritative.

### Rule 2: Consumers Pin Versions
Every `consumesContracts` entry carries a pinned version (`@^1.2`). The L3 copy is stamped with that pinned version.

### Rule 3: L3 Copies Are Read-Only
Pushed-down copies carry the read-only header. A team edits only the contracts it owns, and only at the L2 source (GOV-TT-006 enforces this downstream).

### Rule 4: Generate Only Used Formats
OpenAPI/AsyncAPI/JSON-schema generated only where the AP defines them. No speculative contracts.

### Rule 5: Registry is L2, Sole-Writer DWG
`registry.yaml` lives in `{slug}-management/contracts/` (L2) with a `DO NOT EDIT MANUALLY` header. When polyrepo, the registry may be its own repo; read-only copies still push to each member.

## Edge Cases

| Situation | Response |
|-----------|----------|
| `workspaceTopology: single` | SKIP — no cross-workspace seam; contracts stay in the single workspace |
| No `team-context-registry.md` | Derive producer/consumer from CODEOWNERS `contracts/` ownership + MS-06 (name-based) |
| `microservices` extension absent | Registry still built; compatibilityPolicy defaults to `backward` (safe) |
| A contract with no external consumer | Register it under its owner; no read-only copy pushed to other teams |
| polyrepo layout | Authoritative registry may be its own repo; read-only pinned copies pushed per member repo |
